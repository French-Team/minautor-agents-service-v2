# Protocole — Auto-Améliorer le Cerveau
---

## Objectif

Permettre au cerveau-projet de s'améliorer en continu, en veillant à ce que toutes les sections restent cohérentes et à jour.

---

## Prérequis

- Lire `index-cerveau.md` pour comprendre l'état actuel
- Lire `demarrer.md` pour connaître les protocoles
- Lire `convention-autoamelioration.md` pour les principes
- Lire `protocole-gestion-defaillances.md` pour les défaillances

---

## Étapes

### Étape 1 — Diagnostiquer l'état du cerveau

```
1. Lire index-cerveau.md
2. Vérifier le statut de chaque section :
   - conventions : X/Y complètes
   - regles-immuables : X règles créées
   - protocoles : X protocoles créés
   - recherches-web : structure créée
   - classeur-variables : structure créée
3. Identifier les sections incomplètes ou obsolètes
4. Noter les prochaines étapes
```

### Étape 2 — Identifier les améliorations nécessaires

```
Pour chaque section, vérifier :
1. Est-ce à jour ?
2. Est-ce cohérent avec les autres sections ?
3. Est-ce que les agents l'utilisent correctement ?
4. Est-ce qu'il manque des éléments ?
```

### Étape 3 — Planifier les améliorations

```
1. Lister les améliorations nécessaires
2. Les prioriser (urgent > important > mineur)
3. Créer un pense-bête pour chaque amélioration majeure
4. Créer une spec si nécessaire
5. Créer un todo avec les étapes
```

### Étape 4 — Appliquer les améliorations

```
Pour chaque amélioration :
1. Appliquer en suivant les conventions
2. Mettre à jour les fichiers concernés
3. Mettre à jour les index
4. Valider par RVAV
```

### Étape 5 — Valider la cohérence

```
1. Vérifier que toutes les sections sont cohérentes
2. Vérifier que les liens sont corrects
3. Vérifier que les conventions sont respectées
4. Vérifier que les protocoles sont à jour
5. Appliquer protocole-gestion-defaillances si défaillance détectée
```

### Étape 6 — Documenter l'amélioration

```
1. Mettre à jour index-cerveau.md (prochaines étapes)
2. Mettre à jour le fichier concerné (historique)
3. Ajouter une entrée dans les recherches-web si nécessaire
4. Signer : "[nom-agent] -- [date]"
```

---

## RVAV

Appliquer le cycle complet à chaque étape critique :
- [rechercher] — vérifier les impacts
- [vérifier] — confirmer la cohérence
- [analyser] — valider les conséquences
- [valider] — approuver l'amélioration

---

## Pièges courants

| Piège | Éviter |
|---|---|
| Améliorer sans vérifier | Toujours lire les fichiers concernés |
| Créer des doublons | Vérifier l'existence avant de créer |
| Oublier les dépendances | Utiliser code_searcher |
| Ne pas documenter | Toujours mettre à jour l'historique |
